Why Fleet Dispatch Still Runs on Mile Markers, Not GPS Pins

September 25, 2026 4 min read

A driver calls in: "I'm at mile marker 184 on I-80." Dispatch already has that truck's position on a map, from telematics. Neither one is wrong. They're just not the same format, and somewhere in the middle, somebody has to translate between them by hand, usually while something is already going wrong.

The mismatch, plainly

A telematics platform records a truck's position the way its GPS chip reports it: a latitude and longitude. State DOTs, 911 dispatch, and roadside assistance all work the other way — by route and mile marker — because that's the language the road itself is built in. Mile marker signs, DOT incident logs, and highway patrol reports all reference the same route-and-mile system. Virginia DOT puts it plainly in its own driver guidance: “When calling #77 or 911 for emergency assistance, providing the information on a mile marker sign will help responders reach you quickly.”

A coordinate doesn't fail. It just doesn't match anything

The GPS fix itself is usually precise. The problem is what happens next: a dispatcher who wants to know whether that stretch is closed, under construction, or under a chain restriction has to convert the truck's coordinate back into a route and mile marker, then go look that up somewhere else. It compounds when the call comes from a phone instead of the truck's own telematics — wireless 911 location is only required to be accurate for 80% of calls, and a highway, where cell towers line up in a row, is close to the textbook case where triangulation gets it wrong (FCC E911 location-accuracy rules).

One feed, already tied to the mile marker

MileCheck's road-conditions layer is built from the other direction. Every alert — closure, crash, construction, chain control — arrives already tied to a route and mile marker, because that's how the state DOT that issued it filed it in the first place. Hand it a vehicle's GPS position and it runs the same lookup the phone app runs: nearest mile marker, on this route, in this direction, against live DOT data, instead of a coordinate that has to be looked up somewhere else.

It's already running this way inside one fleet platform. The MileCheck Add-In for MyGeotab and Geotab Drive reads a vehicle's position straight from the Geotab API and returns the nearest mile marker plus the live alerts ahead — direction, distance, and severity included — with no manual lookup in between.
